## What Doesn't Work

- **2026-06-19** — Two separate `formatCost` implementations (in `RunCostBadge` and the trace-drawer `helpers.ts`) drifted: the badge used `toExponential` for `< $0.001`, so the timeline showed an unreadable "$7.3e-4" while the trace tile showed "$0.0007". Fixed by extracting ONE `formatCost` to `src/lib/cost.ts` consumed by both. Lesson: a display formatter used in >1 place belongs in a shared module from the start. Evidence: `client/src/lib/cost.ts`.
- **2026-06-19** — A hover popover positioned `absolute` inside the PR-list table got clipped by the table card's `overflow: hidden`, and a `top: 100% + gap` offset made it close before you could reach it (the pointer crosses empty space → `onMouseLeave` fires). Fix: render the popover `position: fixed` anchored via `getBoundingClientRect` (escapes the `overflow:hidden` ancestor) + a ~160ms close delay that the popover's own `onMouseEnter` cancels, so the pointer can travel onto it and scroll. Evidence: `client/src/components/FindingsSummary/FindingsSummary.tsx`.

- **2026-07-18** — A viewport-geometry scroll-spy is the WRONG tool for a page whose sections are MODEL-GENERATED: their count, height and content are unknown at design time, so any "which section is active" heuristic is tuned against one repo's layout and misbehaves on the next. Onboarding's "On this page" ToC went through two, each shipping a DIFFERENT wrong highlight: (1) a reading-line threshold (`rect.top <= 140`) meant the trailing sections could never activate — at the end of the page there is no scroll room left for them to cross the line, so "Guided reading path" was unreachable; (2) largest-visible-area let one tall section (architecture + its Mermaid diagram) starve every short one, so the small "Critical paths" never won. Adding an end-of-scroll override to (1) just made it skip a section instead. Settled on EXPLICIT SELECTION ONLY: the active entry is parent state (`OnboardingView.selectedKind`) set by a ToC click or a section-header click (`SectionCard.onActivate`) — which deleted every effect, ref, listener and rAF from `TableOfContents` (128 → 58 lines) and has no edge cases. Do not "fix" this back into a scroll-spy without new information. Evidence: `.../OnboardingView/TableOfContents.tsx` (the rationale is in its header comment), `.../OnboardingView/OnboardingView.tsx`.
- **2026-07-18** — The two ContextTab mutations (`useSetAgentContextDocuments`/`useSetSkillContextDocuments`) are fire-and-forget: components call `.mutate(next)` with no `onError` and never read mutation state, so a FAILED attach/reorder POST is invisible — the optimistic local order persists until the parent query refetch resets it. No AC required an error path, but future implementers should add one before test-writers go looking for it (there is nothing to assert today). Evidence: `app/agents/[id]/.../ContextTab/ContextTab.tsx`, `lib/hooks/context.ts`.

## Codebase Patterns

- **2026-07-18** — Agent-editor and skill-editor `ContextTab` are full copy-paste duplicates (component + `helpers.ts`, ~230 lines each; only entity type, mutate hook, and the skill-side "Serializes as" block differ) — so client tests MUST be duplicated per side to protect both, and any attach/reorder UX change lands twice. Flagged needs-discussion by architecture review; consolidation candidate (shared home next to `lib/hooks/context.ts`). Same for `fileName`/`folderPath`/`rootBadge` tripled across both tabs + `ProjectContextView`.
- **2026-07-18** — Skill-editor tab registration is TWO files, not the agent editor's three: `app/skills/[id]/page.tsx` derives `VALID_SKILL_TABS` from the `TABS` array in `SkillEditor/constants.ts` (`TABS.map(t => t.key)`), while the agent side keeps an independent `VALID_TABS` literal in its `page.tsx` that must be edited separately. Evidence: `SkillEditor/constants.ts:21`, `app/agents/[id]/page.tsx:15`.
- **2026-07-18** — i18n namespaces need NO registration: `src/i18n/request.ts` merges every `messages/en/*.json` via `readdirSync` — dropping a new `<ns>.json` file is the entire step. Related trap: `messages/en/context.json` already existed as STALE scaffolding for a never-built reindex page (zero consumers, verified by grep) and was replaced wholesale — grep for `useTranslations("<ns>")` consumers before assuming an existing namespace file is live.
- **2026-07-18** — The `@devdigest/ui` `Checkbox` renders `role="checkbox"`+`aria-checked` but has NO accessible name unless the optional `label` prop is passed — tests must select by row order (`getAllByRole("checkbox")`); draggable rows are reachable via `getByText(name).closest('[draggable="true"]')`. And a `.nullish()` field added to a vendored contract does NOT trip the TS2719 `Partial<>`-fixture break — the 2026-06-19 rule below bites only for REQUIRED fields. Evidence: `src/vendor/ui/kit/Checkbox.tsx:25-29`, `RunTraceDrawer.test.tsx`.
- **2026-06-27** — A repo-scoped page that is NOT under `/repos/[repoId]/...` (e.g. `/conventions`, a workspace-level route) gets the active repo from `useActiveRepo()` in `lib/repo-context` — it returns `{ repoId, activeRepo, repos, reposLoaded }`, resolving repoId from the URL → localStorage `dd-repo` → first repo. Use `activeRepo.full_name` for display (split on `/` for the bare name). Evidence: `app/conventions/_components/ConventionsView/ConventionsView.tsx`, `lib/repo-context.tsx`.
- **2026-06-26** — `@devdigest/ui` `FormField` takes ReactNode `label`/`hint` AND a `right` slot (rendered top-right of the field) — use it for inline field metadata instead of a hand-rolled header row. The Skill editor's Config tab puts the `unsaved` indicator + `~N tokens` estimate (≈ `Math.ceil(body.length/4)`) in `right`, and conditionally renders a `Version message (optional)` input only when `body !== skill.body`. Evidence: `app/skills/[id]/_components/SkillEditor/_components/ConfigTab/ConfigTab.tsx`, `src/vendor/ui/kit/FormField.tsx`.
- **2026-06-26** — Adding a tab to the Agent Editor touches THREE places that must agree: `VALID_TABS` in `app/agents/[id]/page.tsx` (else the `?tab=` is rejected and falls back to `config`), the `TABS` array in `AgentEditor/constants.ts` (the visible tab), and the render switch in `AgentEditor.tsx` (which component renders). The `agents.skills.*` i18n keys + `editor.tabs.skills` already existed as a stub. Evidence: `app/agents/[id]/_components/AgentEditor/`.
- **2026-07-18** — A `NAV` item's `key` string must match in THREE places or you get RUNTIME breakage, not a compile error: (1) `NavItemDef.key` in the vendored `src/vendor/ui/nav.ts`, (2) the `shell.nav.<key>` message in `messages/en/shell.json` — the command palette builds each go-to command via `t(\`nav.${it.key}\`)` (`components/app-shell/hooks/useShellCommands.ts:24`), and (3) the active-route resolver `components/app-shell/helpers.ts` (maps the current pathname → the key it highlights in the sidebar). Adding "Onboarding Tour" with `key:"onboarding"` while `helpers.ts` + `shell.json` already used the convention `onboarding-tour` produced a console `MISSING_MESSAGE: shell.nav.onboarding` on EVERY page (the palette builds nav commands globally) AND left the sidebar item never rendering active — both invisible to `pnpm typecheck` and `pnpm test`, only caught by reading the browser console. Evidence: `src/vendor/ui/nav.ts`, `messages/en/shell.json:19`, `src/components/app-shell/helpers.ts:29`, `useShellCommands.ts:24`.
- **2026-06-26** — `react-markdown@9` sanitizes URLs by default (`defaultUrlTransform` strips `javascript:` and other dangerous schemes), so rendering UNTRUSTED imported skill bodies through the `@devdigest/ui` `Markdown` primitive is XSS-safe with no extra config — a pr-self-review flagged a `[x](javascript:…)` XSS as CRITICAL but it's a false positive on v9. If the primitive ever pins an older react-markdown or sets a custom `urlTransform`, re-check. Evidence: `src/vendor/ui/primitives/Markdown.tsx`, `package.json` (`react-markdown ^9`).
- **2026-06-19** — PR-list table columns are driven by THREE things that must stay aligned: `GRID` (CSS grid-template-columns) + `COLUMN_KEYS` in `app/repos/[repoId]/pulls/constants.ts`, and the matching `list.columns.<key>` in `messages/en/prReview.json`. Adding a column (e.g. `cost`) means updating all three or the header/cells misalign. Evidence: `client/src/app/repos/[repoId]/pulls/constants.ts`.
- **2026-06-19** — `@devdigest/shared` is a vendored copy that must mirror the server's; cost work added `cost_usd` to `RunSummary` + `PrMeta` in `client/src/vendor/shared/contracts/trace.ts` & `platform.ts` in lock-step with the server copy.
- **2026-06-19** — `ReviewRecord` (`contracts/review-api.ts`) carries no cost/token data — only `RunSummary` does. To show cost in a per-review accordion, thread the `RunSummary` by `run_id` from the parent: `FindingsTab` builds a `Map<run_id, RunSummary>` and passes it to `ReviewRunAccordion`. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/FindingsTab/FindingsTab.tsx`.
- **2026-06-19** — Trace-drawer Stats tiles render in `TraceBody.tsx` from `trace.stats` (`RunStats`). Adding a tile = (1) add the field to `RunStats` in both vendor copies, (2) a `<Stat>` in `TraceBody`, (3) a formatter in the drawer's `helpers.ts`, (4) an i18n key under `runs.json` → `trace.stat.*`. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/_components/RunTraceDrawer/_components/TraceBody/TraceBody.tsx`.
- **2026-06-19** — PR-page findings-by-severity filter is threaded top-down: `FindingsTab` counts findings across all runs + holds the active severity, renders `SeverityFilter` (reuses `@devdigest/ui` `SeverityBadge` chips), hides runs with no matching finding, and forwards `severityFilter` → `ReviewRunAccordion` → `FindingsPanel` → `visibleFindings(findings, hideLow, severity)`. Works unchanged for historical runs — `severity` is an existing required field on every finding (no migration). Evidence: `.../SeverityFilter/SeverityFilter.tsx`, `.../FindingsPanel/helpers.ts`.
- **2026-06-19** — Findings-by-severity icon-counts + hover popover are one shared component `@/components/FindingsSummary` (uses `SEV`/`CAT` from `@devdigest/ui`). Reused in TWO places: PR-list FINDINGS column (`PRRow`, fed by `PrMeta.findings_*` counts + `PrMeta.findings` preview) and the PR-detail timeline per-run (`RunHistory`, fed by `findingsByRunId` built in `FindingsTab` from the already-loaded review records — no server call). `@devdigest/ui` exports `SEV`/`CAT` value maps (severity/category → {c,bg,icon,label}). Evidence: `client/src/components/FindingsSummary/FindingsSummary.tsx`.
- **2026-07-12** — Forcing a collapsed panel open AND scrolling to content inside it can't be one synchronous step — the target DOM node doesn't exist until the `open` state commits and re-renders. Working pattern: a ref to stash the pending target + two `useEffect`s, the second keyed on `open` (plus an instruction identity like a nonce) so it only acts once the DOM is actually there. Same shape as `ReviewRunAccordion.tsx`'s pre-existing `targetRunId`/`targetNonce` idiom, generalized to a two-level (section + card) collapse. Evidence: `client/src/components/diff-viewer/FileCard/FileCard.tsx`, `client/src/app/repos/[repoId]/pulls/[number]/_components/ReviewRunAccordion/ReviewRunAccordion.tsx`.

- **2026-07-15** — `hooks/repo-intel.ts` (`useRepoIntelStatus`/`useResyncRepoIntel`) and the older `useReindexContext` (`hooks/core.ts`) both call real, working backend endpoints (`GET /repos/:id/index-state`, `POST /repos/:id/resync` / `context/reindex`) but neither is imported by ANY component under `src/app` — there is currently no "Indexed" badge or manual resync trigger anywhere in the UI, despite `server/src/modules/repo-intel/README.md` describing it as day-1 starter infra. - **2026-07-15** — The click-to-line jump pattern (see the 2026-07-12 entry below) now has a third generalization: Blast Radius's caller rows jump ACROSS TABS (Overview → Files changed), not just within one. `page.tsx` decides the mechanism per click: if the target path is in the current PR's diff (`diffPaths`, a `useMemo`'d `Set<string>` of `pr.files` paths), switch tabs + reuse the existing `targetPath/targetLine/targetNonce` prop chain down through `DiffTab`/`SmartDiffViewer`/`DiffViewer`/`FileCard`; otherwise `window.open(githubBlobUrl(...), "_blank", "noopener,noreferrer")` since a caller is typically a file the PR never touched. `SmartDiffViewer` folds the external instruction into its OWN pre-existing internal `jumpTarget` state via one `useEffect`, so downstream components (`RoleGroup`, `FileCard`) stay unaware a second trigger source exists. Evidence: `client/src/app/repos/[repoId]/pulls/[number]/page.tsx` (`handleJumpToCode`), `.../DiffTab/_components/SmartDiffViewer/SmartDiffViewer.tsx`.

- **2026-07-15** — `messages/en/blast.json` already ships `view.tree`/`view.graph` and `graph.empty`/`graph.ariaLabel` i18n keys — pre-seeded scaffolding for a Tree/Graph toggle that was NEVER built (BlastCard only renders Tree; no toggle UI, no graph renderer, both keys sit unused). ## Tool & Library Notes

- **2026-07-12** — This project's client test suite has ZERO `userEvent` usage anywhere and `@testing-library/user-event` isn't installed (`client/package.json`) — every existing interaction test (`SeverityFilter.test.tsx`, `FindingCard.test.tsx`, `RunTraceDrawer.test.tsx`, `FindingsSummary.test.tsx`) uses `fireEvent` from `@testing-library/react` exclusively. The generic `react-testing-library` skill's own template defaults to `userEvent` — following that default verbatim here hits a module-resolution error.
- **2026-07-18** — To vary a `vi.mock`ed hook's return per test, use a `vi.hoisted(() => ({holder}))` object read by the mock factory; and never call `mockX.mockReturnValue(...)` INSIDE a shared render helper — it silently overrides any `mockImplementation` a test set before calling the helper (last-configured wins). Pass per-test behavior INTO the helper instead. Evidence: `RunTraceDrawer.test.tsx` (`vi.hoisted`), `AgentEditor/.../ContextTab.test.tsx` (`renderTab(agent, previewImpl?)`).
- **2026-07-12** — jsdom 25 (this project's pinned version) does NOT implement `Element.prototype.scrollIntoView`, and `client/src/test/setup.ts` has no polyfill — any component calling `.scrollIntoView(...)` under test must optional-chain it (`el?.scrollIntoView?.(...)`) or the test throws. Separately, jsdom's CSSOM round-trips `var(--custom-property)` tokens through shorthand style properties (`background`, `boxShadow`) losslessly via direct `element.style.<prop>` access — a reliable, mock-free way to assert CSS-variable-driven visual states (highlight/active/etc.) in this codebase's all-inline-style convention. Evidence: `client/src/components/diff-viewer/FileCard/FileCard.tsx`, `client/src/test/setup.ts`.
- **2026-07-18** — `src/lib/hooks/` had ZERO hook tests before Onboarding (every client `*.test.tsx` was a component test; no `renderHook` usage existed anywhere). The working harness for a TanStack Query hook: `renderHook(() => useX(), { wrapper })` where `wrapper` mounts a `QueryClientProvider` built with `new QueryClient({ defaultOptions: { queries: { retry: false } } })`, mocking the single I/O seam `@/lib/api` (`../api`) via `vi.mock` rather than `fetch` (msw is NOT installed). Assert cache writes with `queryClient.getQueryData(key)`. Evidence: `src/lib/hooks/onboarding.test.tsx`.
